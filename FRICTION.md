# FRICTION

Append-only log of every rough edge in the multi-harness run. **One line per moment.** Capture
tooling friction *and* "this phase/handoff exists only because humans needed it" observations.
A messy run that captures ten "ugh" moments beats a clean run that captures none.

**Tags:** `[scaffold]` (pre-run setup) · `[architect]` · `[execute]` · `[review]` · `[qa]` ·
`[handoff]` (friction that lives *between* phases). Newest at the bottom.

---

- `[scaffold]` 2026-07-16 — **The provisioning agent produced a FALSE-ABSENCE finding about Codex subagents** (corrected 2026-07-17 after Jarod's review). The scaffold pass claimed `.codex/agents/*.toml` "does not exist," reasoning from an empty `~/.codex/agents/` + a top-level `codex --help` with no `agents` subcommand — and skipped the authoritative docs (treated them as "optional confirmation"). **The spec was right; the finding was wrong.** Codex custom subagents are real, project-scoped TOML in `.codex/agents/` (docs: developers.openai.com/codex/agent-configuration/subagents); verified live by delegating to a provisioned `executor.toml`, which spawned and returned its own instructions. Lesson (→ `tasks/lessons.md`): a shallow live probe yields false *absences* as readily as false *presences* — "absent from `ls`/`--help`" ≠ "feature doesn't exist." Verify a surface's EXISTENCE against authoritative docs before writing "does not exist." This is a sharper U10 requirement than the original (wrong) entry: the provisioner must not encode absence from a cursory scan.
- `[scaffold]` 2026-07-16 — **The QA squad was authored at USER scope.** The four `qa-*` agents and the `qa-gate` skill were sitting in `~/.cursor/agents/` and `~/.cursor/skills/`, applying to *every* repo on the machine — global-scope pollution. An agent writing config at the wrong scope is *literally* the provisioning problem this whole system exists to solve. Rebuilt project-scoped under `.cursor/`; the user-level copies were deleted after the project copies were committed.
- `[scaffold]` 2026-07-16 — **No browser MCP for the Cursor CLI.** The `qa-browser-e2e` lane needs Playwright/browser tooling, but Cursor's user-level `mcp.json` registers none. Closing the gap **project-scoped** in `.cursor/mcp.json` — registering it at user level would have repeated the wrong-scope friction above.
- `[scaffold]` 2026-07-16 — **Every role file exists twice.** `blueprint/` holds the SSOT; the native harness locations hold hand-copied provisioned duplicates, with no sync between them. Editing intent means editing two files and remembering the mapping. This hand-provisioning ceremony is exactly what an automated provisioner must own.
- `[scaffold]` 2026-07-18 — **The Herdr orchestration was authored against `--help` assumptions and was wrong in three ways — caught only by driving a live Codex pane.** (1) I encoded `herdr agent send` to submit prompts; `agent send`/`send-text` write literal text **without Enter**, so the task would never submit — the real primitive is `herdr pane run <pid> "<text>"` (text + Enter). (2) I read pane output with `--source recent`; an agent TUI uses the alternate buffer, so recent is **empty** — must use `--source visible`. (3) I encoded `herdr agent start … -- <argv>`; the verified pattern is `pane split` → read `pane_id` → `pane run <pid> "codex"`. All corrected in `workflow.md`. Meta-lesson (same spine as the Codex false-absence entry): verifying a control surface against `--help` is not verifying it *works* — drive it.
- `[scaffold]` 2026-07-18 — **`idle` ≠ ready.** Herdr reported the freshly-launched Codex pane as `agent_status: idle`, but the screen was a **directory-trust dialog** ("Do you trust the contents of this directory?"). Submitting the task then would type into the dialog, not the composer. The orchestrator must `pane read --source visible` after idle and clear dialogs (`pane run <pid> "1"`) before sending the task. Herdr status alone is not enough to know an agent is task-ready.
- `[scaffold]` 2026-07-18 — **Codex auto-updated on interactive launch** (0.144.0 → 0.144.6), ran the updater instead of opening the TUI, and dropped back to a shell — so the next prompt hit a dead shell. Orchestration must re-check `pane get` shows `agent: codex` after launch, not assume the spawn produced a live agent.
- `[scaffold]` 2026-07-18 — **Codex is eager and auto-approved.** From a trivial verification prompt (which explicitly said "do not run commands"), Codex read `AGENTS.md`, and an auto-approver let it run `git switch -c feat/subscription-crud` on its own — moving the shared working tree off `main`. Harmless here (branch == main; I restored main + deleted it), but it shows Codex will act on repo context immediately and an auto-approval mechanism is live. Desired during the real run; a surprise during verification.
- `[scaffold]` 2026-07-18 — **Cursor prompts to approve the project MCP on every launch.** Launching `agent --model composer-2.5` in a Herdr pane opens on an **MCP Server Approval** dialog for the `playwright` MCP (good news: it proves `.cursor/mcp.json` is picked up). Reported by Herdr as `idle` (the same `idle` ≠ ready trap). Must be accepted or `qa-browser-e2e` loses Playwright. The accept keystroke is a **bare** `herdr pane send-keys <pid> a` — `pane run "a"` does **not** work (its trailing Enter breaks the selection), the opposite of Codex's numbered dialog which took `pane run "1"`. Model resolved to Composer 2.5 (no fallback).
- `[scaffold]` 2026-07-18 — **`pane run` does not submit to Cursor's composer.** Verified live: `pane run "<text>"` *types* the prompt into Cursor's composer but its bundled Enter becomes a **newline**, not a submit — the prompt just sits there. A discrete `herdr pane send-keys <pid> Enter` submits it (Cursor then replied correctly). Codex, by contrast, submits fine with `pane run` alone. So the submit primitive is **agent-specific**, and the QA-gate step would have silently hung (contract typed, never sent) without this. Corrected in `workflow.md`.
- `[execute]` 2026-07-18 — **Codex logs an MCP startup failure on every launch in this repo:** `⚠ MCP client for 'node_repl' failed to start: No such file or directory (os error 2)`. It's a stale/global Codex MCP entry (not project-scoped, not in `.codex/`) and irrelevant to the Executor's file/shell work — Codex went `working` and proceeded normally. But it's noise the orchestrator has to read past on the very pane it's watching, and a clean run shouldn't surface an unrelated MCP error at all. Cosmetic, logged for completeness.
- `[execute]` 2026-07-18 — **The version-pinned React Router scaffold still copied the moving default template.** `create-react-router@7.9.4` generated package dependencies at React Router 8 because the template source had advanced. The Executor had to pin all framework packages back to `7.9.4` manually; a version flag that does not version the template is a bootstrap footgun.
- `[execute]` 2026-07-18 — **React Router dev exhausted macOS file watchers in the multi-harness checkout.** `bun run dev` failed immediately with `EMFILE` even at a raised file-descriptor limit. `CHOKIDAR_USEPOLLING=1` made the same command reliable, so the dev script now carries that environment setting.
- `[execute]` 2026-07-18 — **Bun's native SQLite driver cannot cross the RR7 SSR runtime boundary.** Data tests using `bun:sqlite` were green, but the React Router dev server evaluates server modules in Node and returned HTTP 500 on the unsupported `bun:` URL scheme. The app adapter now uses `better-sqlite3` for Node SSR while the injected Drizzle data layer remains covered under Bun's native in-memory driver.
- `[execute]` 2026-07-18 — **The installed Playwright CLI warns that both provisioned skill copies are stale on every command.** Browser automation still worked, but each snapshot/fill/click printed two large upgrade banners (`.claude/skills` and `.agents/skills`), heavily obscuring the acceptance evidence. The skills should be refreshed together before the next gate.
- `[execute]` 2026-07-18 — **The step-2 completion wait (`herdr wait agent-status --status idle`) rode out its full timeout instead of firing at completion.** Codex finished at 42m01s, but the watched pane was backgrounded/unfocused, so Herdr recorded the completion as `done`, not `idle` (its seen-semantics: a completion in an unfocused/background pane becomes `done`). The `--status idle` wait never matched and returned only at the 45-min timeout — a ~3-min blind tax here, but *unbounded* in general (a fast task wastes the entire timeout before the orchestrator wakes). Fix: for a backgrounded executor pane, wait on `--status done` — or better, a content sentinel via `wait output --match` (exactly what the QA-gate step already does with `gate_verdict`). workflow.md step-2 hedged "# or --status done if backgrounded"; this run proves `done` is the real case, so it should be the default, not the aside.
- `[qa]` 2026-07-19 — **The "Cursor prompts to approve the playwright MCP on every launch" assumption did NOT hold.** Launching plain `agent --model composer-2.5` this run opened straight on the composer — no MCP-approval dialog — so the workflow's `send-keys a` step had nothing to accept (a bare `a` would have typed into the composer). Likely the approval was remembered from the 2026-07-18 smoke, or cursor-agent v2026.07.16 changed the behavior. Lesson: the launch-dialog state is NOT stable across runs/versions — always `pane read` and branch on what's actually there, never script a fixed keystroke blind. Mooted anyway by `--approve-mcps` (next entry).
- `[qa]` 2026-07-19 — **★ THE run-1 Phase-4 finding: an interactive Cursor QA gate cannot be driven through Herdr — the documented loop was broken as written.** Cursor prompts **per command** ("Run this command? Not in allowlist: cd"), and Herdr's `send-keys` cannot deliver Cursor's approval chords: `Tab` ("allowlist") and `Shift+Tab` ("Run Everything") **both collapse to a single-approve** — proven live (three keystrokes → three single-advances; allowlist never sticks; "Run Everything" never triggers). So there is no way to escalate to session-wide auto-run from inside the dialog, and hand-approving every git/lsof/bun/playwright command across three lanes is untenable. **Fix:** launch `agent --model composer-2.5 --force --approve-mcps` — `--force`/`--yolo` IS the dialog's "Run Everything," just as a startup flag; it keeps the interactive TUI and full command visibility (so it honors "Herdr wants interactive panes" — only `--print` headless is the thing to avoid), and `--approve-mcps` removes the MCP dialog. workflow.md Phase 4 corrected. Notably this required **Jarod's explicit authorization** — the permission classifier correctly gated the escalation to unrestricted command execution, and workflow.md had itself (wrongly) forbidden `--force`. Single biggest orchestration correction of run 1.
- `[qa]` 2026-07-19 — **The gate emitted `gate_verdict: PASS`, not the literal `**gate_verdict:**` the contract/parser spec requires.** The TUI rendered (or Composer emitted) the markdown without the `**` emphasis. Unambiguous for a human reading the pane, but a future *automated* verdict parser keying on the exact `**gate_verdict:**` / `**pr_recommendation:**` strings would miss it and mis-gate the PR. Fix options: loosen the parser to tolerate optional `**`, or have the `qa-gate` skill emit the verdict in a fenced plain-text block. Logged, not fixed this run.
